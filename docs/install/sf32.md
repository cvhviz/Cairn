# Installing on the LilyGO T-Display SF32

The T-Display SF32 uses a **SiFli SF32LB52**, not an nRF52 or ESP32, so it has no UF2 drive and no web flasher. Cairn's download includes everything needed, including SiFli's flashing tool, so installing is one double-click.

Installing and updating are the same steps. Your identity, contacts, channels and settings are kept.

## Quick install

1. Download **`MeshCore-TDisplaySF32-CairnN-<date>-install.zip`** from the [latest release](https://github.com/cvhviz/Cairn/releases/latest) and unzip it.
2. Plug the board into your computer with a **USB-C data cable**. Some cables only charge.
3. Run the installer for your computer:

| Computer | Run | First time only |
|---|---|---|
| **Mac** | double-click **`Install on Mac.command`** | If macOS says it can't be opened, go to **System Settings › Privacy & Security**, click **Open Anyway**, then double-click it again. |
| **Windows** | double-click **`Install on Windows.bat`** | Install the [WCH CH343 driver](https://www.wch-ic.com/downloads/CH343SER_EXE.html). If Windows SmartScreen appears, click **More info › Run anyway**. |
| **Linux** | `./install-linux.sh` in a terminal | Add yourself to the serial group (`sudo usermod -aG dialout $USER`, or `uucp` on Arch), then log out and back in. |

The installer finds the board by its USB chip, writes Cairn and restarts the board. This takes about two minutes. If more than one T-Display SF32 is plugged in, it asks which one to use. You can also name the port yourself: `"Install on Windows.bat" COM5` or `./install-linux.sh /dev/ttyACM0`.

## Updating later

Once Cairn is on the board, later builds can be installed over Wi-Fi from the board itself: **Settings › System › Firmware update**. The board checks this repository's latest release for `MeshCore-TDisplaySF32-CairnN-<date>-update.bin`, checks the file's SHA-256, then writes it to its spare slot. If the new build doesn't start properly, the board goes back to the old one. You can always update over USB with the steps above instead.

## If it doesn't work

| What you see | What to do |
|---|---|
| "No board found" | Use a data cable and plug it directly into the computer rather than a hub. On Windows, check Device Manager › Ports for **USB-SERIAL CH343**. If it isn't there, install the driver. |
| "didn't connect", "Failed to connect to the chip" | Unplug the board, plug it back in and run the installer again. The installer already retries three times. |
| It keeps failing at the same point | Try another USB port or cable. A slower link helps on some computers: run it with `SF32_BAUD=115200` (macOS/Linux) or `set SF32_BAUD=115200` first (Windows). |
| The board restarts every few minutes while plugged in | Try another cable and plug it straight into the computer. One test unit did this on a weak USB supply, and we're still looking into it. Please [report it](https://github.com/cvhviz/Cairn/issues/new?template=bug_report.yml). |

The SF32's download mode is built into the chip's ROM, so a failed or interrupted install can't brick the board. Run the installer again.

## By hand

The zip's `firmware/` folder holds three files, and `tools/` holds [OpenSiFli sftool](https://github.com/OpenSiFli/sftool) 0.2.5 (Apache-2.0, unchanged release builds). To use your own sftool (0.2.5 or newer):

```bash
sftool -c SF32LB52 -p <port> -b 230400 --compat true write_flash \
  firmware/bootloader.bin@0x12010000 firmware/main.bin@0x12020000 firmware/ftab.bin@0x12000000
sftool -c SF32LB52 -p <port> -b 230400 --compat true erase_region 0x12700000:0x2000
```

| Part | Address |
|---|---|
| bootloader (with Cairn's update-slot selector) | `0x12010000` |
| main image | `0x12020000` |
| flash table (ftab) | `0x12000000` |

The second command clears the Wi-Fi update records, so the board starts the image you just wrote even if an earlier Wi-Fi update left the other slot active. It doesn't touch your data.

`<port>` is the CH343 port, for example `/dev/cu.wchusbserial5B91…` on macOS, `/dev/ttyACM0` on Linux or `COM5` on Windows. The default 1 Mbaud is unreliable on the CH343, so use 230400 with `--compat true`.

## Going back to the factory firmware

LilyGO's factory image installs the same way, with `sftool write_flash` of their files. See [LilyGO's T-Display SF32 repository](https://github.com/Xinyuan-LilyGO/T-Display-SF32).
