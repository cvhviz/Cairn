# Installing on the LilyGO T-Display SF32

The T-Display SF32 uses a **SiFli SF32LB52**, not an nRF52 or ESP32, so it has no UF2 drive and no web flasher. Cairn's download includes everything the install needs, including SiFli's flashing tool, so installing is one double-click and takes about a minute.

Installing and updating are the same steps. Your identity, contacts, channels and settings are kept.

## If your board has the first SF32 build

The first SF32 files (posted 6 Oct 2026, withdrawn 7 Oct) didn't charge the battery, could restart the board on USB, couldn't update over Wi-Fi, and their installer could stall. The files posted on 7 Oct fix all four. A board on the first build needs this USB install once: the Wi-Fi updater only offers a higher build number, and the fixed build is still 107. The new installer can also repair a board the old one left half-written; it may ask you to reset the board while it waits.

## Before you start

1. **Slide the power switch ON, with the battery connected.** With the switch OFF and only USB power, the board restarts every 20 to 40 seconds once the flash tool takes over, and the install fails. If Cairn reports that no charged battery is connected, the installer stops and says so. A flat battery counts as none: charge it for 10 minutes first.
2. **Take the core off the keyboard.**
3. **Plug it into your computer with a USB-C data cable.** Some cables only charge. Plug it straight into the computer rather than a hub.
4. Close anything that uses the board's serial port: a serial monitor, the MeshCore web app, another flasher.

## Install

Download **`MeshCore-TDisplaySF32-CairnN-<date>-install.zip`** from the [latest release](https://github.com/cvhviz/Cairn/releases/latest), unzip it, and run the installer for your computer:

| Computer | Run | First time only |
|---|---|---|
| **Mac** | double-click **`Install on Mac.command`** | If macOS says it can't be opened, go to **System Settings › Privacy & Security**, click **Open Anyway**, then double-click it again. The installer needs Python 3: if it says Python 3 isn't installed, open Terminal, run `xcode-select --install` (Apple's free Command Line Tools), and run the installer again. |
| **Windows** | double-click **`Install on Windows.bat`** | If no board is found, install the [WCH CH343 driver](https://www.wch-ic.com/downloads/CH343SER_EXE.html). If Windows SmartScreen appears, click **More info › Run anyway**. Nothing else is needed: the Windows installer doesn't use Python. |
| **Linux** | `./install-linux.sh` in a terminal | It needs `python3` (pyserial is included). Add yourself to the serial group (`sudo usermod -aG dialout $USER`, or `uucp` on Arch), then log out and back in. |

> **The Windows installer hasn't been run on a Windows PC yet.** It does the same steps as the Mac and Linux one and passed the same offline tests against a simulated board, but nobody has tried it on real Windows. If you do, please [report how it went](https://github.com/cvhviz/Cairn/issues/new?template=bug_report.yml), whether it worked or not.

Leave the board alone until the installer says **Done**: don't unplug it, dock it or touch the switch.

If more than one T-Display SF32 is plugged in, the installer asks which one to use. You can also name the port yourself: `./install-linux.sh /dev/ttyACM0`, `"./Install on Mac.command" /dev/cu.wchusbserial…` from Terminal, or `"Install on Windows.bat" COM5` from a command prompt.

## What the installer does

1. **Finds the board** by its USB chip (the CH343, USB ID `1a86:55d3`).
2. **Gets Cairn ready**, if Cairn is running: the battery charger can't cut the power during the install, the watchdogs are stopped, and the board stays awake. If Cairn reports no charged battery, it stops here.
3. **Starts SiFli's flash tool on the board** and checks that the chip has left its debug mode. That check is new: the first installer left it to the flash tool, which never confirms it, and that is why it could stall.
4. **Writes only what the board doesn't already have**: the bootloader (with Cairn's Wi-Fi update support), Cairn itself and the flash table. A few bytes that the chip could mistake for commands are blanked in the copies it writes; it then puts them back one by one and checks every file's checksum.
5. **Clears the Wi-Fi update records**, so the board starts the firmware just written, and restarts the board.

Anything that fails is tried again, up to three times. Running the installer again is always safe: it checks what is on the board and carries on from there. Each run keeps a log folder (its path is printed at the start and the end); attach it to a bug report.

The SF32's download mode is built into the chip's ROM, so a failed or interrupted install can't brick the board.

## Updating later

Once this build is on the board, later builds install over Wi-Fi from the board itself: **Settings › System › Firmware update**. The board checks this repository's latest release for `MeshCore-TDisplaySF32-CairnN-<date>-update.bin`, downloads it over the keyboard's Wi-Fi, and checks its size, SHA-256 and board marker before it offers to install. The new build goes into a spare slot and runs on trial; it is kept only once it has run for a minute, otherwise the board goes back to the build it had. It needs USB with the battery switched on, or 30 % battery. A board on Cairn 108 gets Cairn 112 this way.

You can always update with the USB installer instead.

## If it doesn't work

| What you see | What to do |
|---|---|
| "No T-Display SF32 found" | Use a data cable, plugged straight into the computer. On Windows, check Device Manager › Ports for **USB-SERIAL CH343**; if it isn't there, install the driver above. On Linux, check you are in the `dialout` group. |
| "No charged battery: the power switch is off or the battery is flat" | Slide the switch ON. If it already is, charge the board for 10 minutes. Then run the installer again. |
| "Can't open the port" | Another program has it. Close serial monitors, the MeshCore web app and other flashers. |
| "Waiting up to 2 minutes for the board" | Nothing on the board answers: a new or empty board, or one a stalled install left behind. Reset it while the installer waits (see below). |
| It stops, or keeps failing at the same point | Reset the board (see below) and run the installer again. Try another USB port or cable. |
| Mac: "Python 3 isn't installed" | Run `xcode-select --install` in Terminal, wait for it to finish, and run the installer again. The installer can also write the firmware with the flash tool alone if you type YES, but that is the old method, which can stall. |
| The board restarts every few minutes while plugged in | That was the first build's charger problem, which this build fixes. If it still happens on this build, please [report it](https://github.com/cvhviz/Cairn/issues/new?template=bug_report.yml). |

**Resetting the board**, from the gentlest:
1. Hold button **A** for 12 seconds and let go. This restarts the chip even when the firmware is stuck.
2. Hold button **D** for about 20 seconds. The battery charger cuts the power for a moment and the board restarts.
3. Slide the power switch OFF, unplug USB, wait 5 seconds, slide the switch ON and plug USB back in.

Unplugging USB alone doesn't restart the board while the switch is ON: the battery keeps it running.

## By hand

The zip holds the firmware in `firmware/`, and in `tools/`: [OpenSiFli sftool](https://github.com/OpenSiFli/sftool) 0.2.5 (Apache-2.0, unchanged release builds for macOS, Windows and Linux), Cairn's helper `sf32link.py`, and [pyserial](https://github.com/pyserial/pyserial) 3.5 (BSD-3-Clause), which the helper uses.

The installer's steps by hand, on macOS or Linux, from the unzipped folder. On Linux use `tools/sftool-linux-x86_64` or `tools/sftool-linux-aarch64`. On Windows, install Python and pyserial (`py -m pip install pyserial`), then use `py` and `tools\sftool-windows-x86_64.exe`.

```bash
export PYTHONPATH=tools/pylib
T=tools/sf32link.py; S=tools/sftool-macos; P=<port>
python3 $T prep $P                                    # stops on "NOBATT": switch ON first
python3 $T escape firmware/bootloader.bin firmware/main.bin firmware/ftab.bin -o esc
$S -c SF32LB52 -p $P --before no_reset --after no_reset read_flash probe.bin@0x12000000:0x10
python3 $T exit $P                                    # must say "the flash stub answers"
$S -c SF32LB52 -p $P --before no_reset_no_sync --after no_reset write_flash \
  esc/bootloader.bin@0x12010000 esc/main.bin@0x12020000 esc/ftab.bin@0x12000000
python3 $T restore $P esc/list.json                   # puts the blanked bytes back, checks every file
$S -c SF32LB52 -p $P --before no_reset_no_sync --after soft_reset erase_region 0x12700000:0x2000
```

| Part | Address |
|---|---|
| bootloader (with Cairn's update-slot selector) | `0x12010000` |
| main image | `0x12020000` |
| flash table (ftab) | `0x12000000` |

The last command clears the Wi-Fi update records and restarts the board, so it starts the image you just wrote even if an earlier Wi-Fi update left another slot active. It doesn't touch your data.

`<port>` is the CH343 port, for example `/dev/cu.wchusbserial5B91…` on macOS, `/dev/ttyACM0` on Linux or `COM5` on Windows. `python3 tools/sf32link.py ports` lists it.

Two things to avoid:
- **A plain `sftool write_flash` with no `exit` step.** sftool never checks that the chip left its debug mode, and if it didn't, the write stalls and the chip stays deaf until it is reset.
- **Lowering the speed with `-b`.** The chip's debug engine follows the current speed, so a stalled flash tool then answers only at that speed until a reset. The installer stays at sftool's default, 1 Mbaud.

## Going back to the factory firmware

LilyGO's factory image installs with `sftool write_flash` of their files. See [LilyGO's T-Display SF32 repository](https://github.com/Xinyuan-LilyGO/T-Display-SF32). The same safe steps apply: `prep`, `escape`, the `read_flash` and `exit` pair, `write_flash` of the escaped copies at their addresses, then `restore`.
